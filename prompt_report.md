# Guidelines

The report should be visually useful but not overloaded.

## Tables

Use clean, readable tables.

### Rules:

- Avoid tables with too many columns.
- Prefer 4 to 7 columns.
- Avoid tables with too many rows.
- Main report tables should usually show top 10, top 20, or summarized results.
- Large tables should go to the appendix.
- Every table should answer a clear question.
- Avoid including raw, messy, or overly detailed tables in the main report.

**Good tables:**

- Top 10 communities by size.
- Top 10 topics by message count.
- Emotion distribution by community.
- Strongest inter-community links.
- Top similar message pairs.
- Descriptive statistics summary.

**Bad tables:**

- Tables with dozens of columns.
- Tables with hundreds of rows.
- Tables that duplicate what a simple sentence can explain.
- Tables without interpretation.

## Plots

Use plots only when they are actually useful.

**Good uses of plots:**

- Showing distributions.
- Showing temporal trends.
- Showing community size imbalance.
- Showing topic or emotion changes over time.
- Showing relationships between two meaningful variables.
- Showing graph structure when readable.

**Bad uses of plots:**

- Plotting three values that can be shown in one sentence.
- Plotting nearly identical values, such as 91, 90, and 89, without a useful reason.
- Creating crowded plots with too many labels.
- Creating decorative plots that do not support interpretation.

**Every plot should have:**

- A clear title.
- Clear axis labels.
- A short explanation below it.
- A reason to exist.

## Writing Style

The report should be concise and analytical.

Style requirements:

- Avoid long paragraphs.
- Prefer short sections.
- Use bullets when appropriate.
- Use concise explanations.
- Do not write verbose text.
- Focus on findings, evidence, and interpretation.
- Make the report readable for someone who wants insight, not just raw output.
- Avoid repeating the same statistics in multiple sections.
- Use tables and plots to reduce unnecessary text.

Preferred structure for interpretations:

1. What the result shows.
2. Why it matters.
3. What question it helps answer.

The code should generate a Markdown report.

The code should:

- Load Graph Version 1.

- Extract relevant node, edge, message, channel, user, community, topic, similarity, and sentiment attributes.
- Compute basic graph statistics.
- Compute community-level statistics.
- Compute topic-level statistics.

- Compute sentiment and emotion statistics.
- Compute temporal statistics when timestamps are available.
- Generate clean tables.

- Saved on `reports/`, following the folder organization of `reports/aletheia_pt_report.md` per example.

The report should not be a dump of all available data. It should be a readable analytical report that highlights the most important patterns in the graph.
